# CRM Solar — інструкція користувача та адміністратора

CRM Solar — закрита система керування проєктами для вашої команди. Увійти можуть
лише користувачі, яких запросив адміністратор: публічної реєстрації немає.

## 1. Щоденна робота

### Вхід і вихід

1. Відкрийте адресу CRM Solar у браузері.
2. Уведіть email і пароль, отримані від адміністратора.
3. Для виходу натисніть кнопку профілю або **Вийти** у лівому меню.

Якщо не можете увійти, не створюйте новий обліковий запис. Зверніться до
адміністратора: він може створити посилання для скидання пароля.

### Навігація

- **Головна** — Delivery Health Dashboard: активні проєкти, відкриті,
  прострочені та заблоковані задачі.
- **Проєкти** — дерево проєктів та їхній стан.
- **Задачі** — загальний список доступних задач.
- **Kanban** — задачі за статусами.
- **Календар** — дедлайни.
- **Журнал** — рішення, ризики, етапи та історія змін.
- **Клієнти**, **База знань**, **Бібліотека**, **Чат** — робочі матеріали й
  комунікація, якщо вони доступні вашій ролі.

На телефоні основні розділи доступні через нижню навігацію. Перемикач мови та
світлої/темної теми зберігає вибір у браузері.

### Робота з проєктом

1. Відкрийте **Проєкти** і виберіть проєкт.
2. Перегляньте overview, етапи, учасників та список задач.
3. Створюйте задачі з чіткою назвою, виконавцем, пріоритетом і дедлайном.
4. Оновлюйте статус під час фактичного руху роботи.
5. Фіксуйте важливі рішення, ризики й контрольні точки у **Журналі**.

Не використовуйте статус «виконано», якщо задача не пройшла потрібну
перевірку. Це зберігає dashboard і календар достовірними.

### Ролі

| Роль | Можливості |
|---|---|
| Адміністратор | Користувачі, налаштування, аудит, усі робочі дані. |
| Менеджер | Створення та керування проєктами і задачами. |
| Учасник | Робота з доступними проєктами, задачами, коментарями та KB. |
| Гість | Обмежений перегляд; доступ визначає адміністратор. |

Права перевіряються сервером. Наявність кнопки в інтерфейсі не є заміною права
доступу.

## 2. Інструкція адміністратора

### Запрошення користувача

1. Відкрийте **Адміністрування → Користувачі**.
2. Натисніть **Запросити**.
3. Уведіть email, виберіть роль і мову листа, потім створіть запрошення.
4. У локальному console-режимі скопіюйте одноразове посилання та передайте його людині приватним каналом. У SMTP-режимі посилання надсилається системою й не повертається API.

Посилання не треба надсилати в загальний чат або зберігати у документах.
Якщо запрошення прострочене, створіть нове. Для вже наявного користувача
потрібно використати скидання пароля, а не нове запрошення.

### Скидання пароля

У списку користувачів відкрийте дії потрібного профілю й створіть reset link.
Скопіюйте його одразу: після закриття діалогу система більше не покаже токен.
Передавайте посилання вручну лише власнику облікового запису.

### Аудит

**Адміністрування → Журнал аудиту** містить входи, зміни ролей, запрошення,
важливі налаштування. Використовуйте фільтр і CSV
експорт для розслідування інцидентів.

### Файли

Файловий модуль може бути вимкнений, доки не налаштовано сховище. У такому
стані це очікувана поведінка, а не помилка: upload і Dropbox не слід обходити
тимчасовими mock-рішеннями.

## 3. Локальний запуск для розробки

### Перший запуск

```bash
pnpm install
cp .env.example .env
```

У `.env` обов’язково задайте `DATABASE_URL` і `SESSION_SECRET`. Після
підготовки PostgreSQL виконайте:

```bash
pnpm run db:migrate
pnpm --filter @workspace/api-server run db:seed
```

`SEED_ADMIN_PASSWORD` має бути заданий явно і містити щонайменше 12 символів.

### Запуск

У двох окремих терміналах:

```bash
pnpm --filter @workspace/api-server run dev
pnpm --filter @workspace/pds-app run dev
```

Відкрийте `http://localhost:5173`. Перевірка API:

```bash
curl --fail --silent http://127.0.0.1:8080/api/healthz
curl --fail --silent http://127.0.0.1:8080/api/readyz
```

## 4. Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| Не вдається увійти | Правильність email/пароля, статус облікового запису, reset link у адміністратора. |
| `readyz` повертає помилку | PostgreSQL, `DATABASE_URL`, доступність бази. |
| Файли недоступні | Перевірте, чи модуль файлів свідомо вимкнено та чи налаштовано storage. |

Для інфраструктури, backup/restore, міграцій і production release використовуйте
детальний [operations runbook](docs/OPERATIONS.md), а не цей користувацький
мануал.
